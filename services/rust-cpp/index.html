What we do

Memory-safety roadmap

Inventory, risk-rank components by exposure and publish a credible, staged plan.

Modern C++ hardening

Current toolchains, sanitisers, hardened standard-library modes, static analysis and fuzzing in CI.

Rust adoption

Pick the right first component, design the FFI boundary and set up build, test and review.

Interop done properly

Safe wrappers with cxx or bindgen, clear ownership rules and no undefined behaviour at the seams.

Characterisation tests

Pin today’s behaviour so modernisation never changes results by accident.

Performance

Profile before and after so safety never quietly costs you latency.

What you get

  • Published memory-safety roadmap
  • Hardened CI with sanitisers and fuzzing
  • First Rust component in production
  • Interop and coding guidelines

How an engagement runs

  1. Diagnose (1–2 weeks). We read the code and the data, and agree the baseline and the number we expect to move.
  2. Prove (3–5 weeks). A thin, real slice in production, measured against that baseline.
  3. Scale and hand over. Widen the change with your engineers, then leave docs, runbooks and a team that owns it.
