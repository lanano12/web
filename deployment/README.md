# Deployment and remaining operational controls

GitHub Pages currently serves `www.nexafusion.io`. The publishing workflow validates the source and uploads only `dist/`, created from the explicit allowlist in `tools/package_site.py`.

## HTTP response headers

The intended policy is in `tools/security_policy.py`. `deployment/headers.json` is the machine-readable policy and `deployment/_headers` is its Cloudflare static-hosting form. These are generated by `tools/build.py`.

**GitHub Pages does not interpret `_headers`.** The HTML CSP is effective there, but HSTS, anti-framing, MIME protection and the other HTTP headers need a host or CDN that applies them. Do not claim those controls are live because these files exist.

For Cloudflare Pages or Workers Static Assets, build a fresh artifact with:

```sh
python3 tools/build.py
python3 tools/check.py
python3 tools/package_site.py --target cloudflare --output /tmp/nexafusion-cloudflare
```

Publish that artifact through the account controlling the domain, configure the custom domain and validate before changing production DNS. Cloudflare documents the format at https://developers.cloudflare.com/workers/static-assets/headers/ . A response-header rule in an existing CDN can instead use the same values in `headers.json`.

HSTS is deliberately host-only: `includeSubDomains` and preload require a separate review of every subdomain and are not assumed safe.

Run `python3 tools/check_live.py` after deployment. A missing header must remain a failing result until production is configured correctly.

## Disclosure

The security policy points to GitHub private vulnerability reporting. Enable it and verify the endpoint before publishing. Confirm that the repository owner's notification route is monitored. The public policy does not claim a response SLA.

## Public history

An allowlisted deployment prevents old source files from being served on the website. It does not remove existing public Git history. Purging personal/demo history requires a reviewed rewrite of every affected published branch, a private recovery backup and explicit approval for the force-push. Copies already downloaded or cached cannot be recalled by changing Git refs.

## Account controls

Keep GitHub and domain administration protected by strong authentication and review recovery access. Account ownership and inbox monitoring cannot be proved by automated source checks.
